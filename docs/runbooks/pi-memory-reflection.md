# 验收后经验复盘（#968）

项目默认关闭，不改变既有项目的自动行为。正式启用、真实模型效果及最终体验验收属于 #973；本实现不启用项目、不部署服务。

通过已认证的 `GET /api/projects/:id/pi/memory-reflection` 读取开关，`PUT` 同一路径、正文 `{"enabled":true|false}` 显式配置。启用仅覆盖此后验收的任务，不回扫旧任务；关闭会终止待消费请求的写权限，重新启用不会复活这些请求。

Host 在 PI 接受或最终判定失败后保存 `pi_memory_reflections` 请求。验收、Evidence 和交付事件的持久化游标补齐“验收已提交、请求尚未保存”的崩溃窗口，每批最多 100 条指定类型事件。Core 只记录和补齐请求，不调用复盘模型。Agentic 启动后每 5 秒领取至多一个请求，不占用 Work 队列，也不依赖普通 manager cycle。

幂等键是项目、Work、终态 Run 和可信证据指纹。同一指纹最多两次尝试（一次正常、一次重试）；租约 60 秒、每次超时 45 秒，过期 token 不能写入。记忆和请求完成状态在同一 SQLite 事务提交；提交前崩溃不留下记忆，提交后崩溃不重新处理。复盘失败、预算耗尽、无新经验均不回滚 Work done。

每次最多 16 条当前 Run 的结构化 Evidence 摘要，摘要上限 48,000 UTF-8 字节。模型总输入预算 128,000 UTF-8 字节（累计计入重复上下文），总输出 3,000 tokens / 16,000 字节，最多 4 次模型调用、6 次工具调用。不启用 SDK 隐式重试或自动压缩。摘要不足、无可信证据及预期无经验都有持久化跳过原因。

复用同一 Supervisor 身份，使用独立内部 `memory_reflection` profile。仅提供 `reflection_evidence_read`、有界项目 `memory_search`、`memory_remember`，无仓库、Shell、能力发现、外部 MCP、技能或任务调度工具。写入继续经过 Action Gate、#966 来源校验和 #967 的修订、去重、用户记忆保护、停用及遗忘保护；同一 Run 已生成经验被停用/遗忘后，新证据指纹也不能通过换 key 复活该来源。自动经验不授予任何执行权限。

`needs_user` 不产生请求。最终失败任务只有 Pi 能从可信证据确定根因时才能保存 `debugging_pattern`，结构化 `outcome=diagnosis_only`，Host 将 resolution 固定为“未验证修复；仅保留排查结论。”。成功修复经验仍要求 trusted passed Evidence；诊断可以引用可信的失败观测，不能声称修复成功。

本地验证使用临时数据库、两个独立连接、重开数据库、领取后崩溃/事务提交失败注入，以及模型替身验证超时、预算、迟到写入和无新经验。真实模型质量及正式运行环境尚需 #973 验收。
