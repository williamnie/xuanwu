# Xuanwu v0.2.4

玄武 `v0.2.4` 扩展了 Telegram 与通用 IM 运行时，强化 Work/Run 热路径和 PI 授权边界，
并将项目许可证切换为 Apache License 2.0。

Xuanwu `v0.2.4` adds Telegram and provider-neutral IM runtime capabilities, strengthens Work/Run
hot paths and PI authorization boundaries, and moves the project to the Apache License 2.0.

## 重点更新 / Highlights

- **Telegram integration**：新增 Telegram 设置面板、长轮询接收、确定性分段投递、审批交互、
  生命周期通知与重启安全 cursor；连接器只有在显式配置后才会启用。
- **Bounded IM context**：为飞书与 Telegram 共用的 IM 上下文增加预算观测、投影 binding、cursor
  和 Session rollover lineage，长会话可以在保持审计连续性的同时有界换代。
- **Work/Run lifecycle**：收紧热路径 claim、Git workspace baseline、执行归属、完成判定与列表摘要，
  减少无效扫描和状态漂移。
- **PI safety and reliability**：修复工具面与对话范围泄漏、授权询问和连续无进展续跑，补齐
  Code Agent 目录发现及 release 环境中的 Codex OAuth 加载。
- **Release and UI**：增加第三方许可、依赖安全、仓库卫生与 provenance 门禁；前端对齐设计系统，
  增加移动端导航抽屉并改善响应式工作台。

## 升级注意 / Upgrade notice

- 本版本包含 additive database migrations `081_telegram_channel_runtime` 与
  `082_im_context_lifecycle`。它们只增加 Telegram/IM runtime 表和索引，不删除或改写既有 authority
  数据；升级前仍应备份并验证 `runner.db`。
- 最低可回滚 binary 为 `v0.2.3`。回滚不会删除新表中的 cursor、binding、delivery receipt 或
  rollover lineage，但旧版本不会使用 Telegram 与新的 IM context lifecycle 能力。
- Telegram 不会在升级后自动启用；必须由 operator 显式配置 connector 与凭据。详细步骤见
  [release, upgrade, and rollback](../runbooks/release-upgrade-rollback.md)。

This release adds migrations `081` and `082`. They create additive Telegram and IM-runtime tables
and indexes without rewriting existing authority data. Back up and verify `runner.db` before
upgrading. `v0.2.3` is the minimum rollback binary; it preserves but does not consume the new
runtime records. Telegram remains disabled until an operator explicitly configures the connector
and credentials.
