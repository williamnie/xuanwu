## 1. 信息架构

### 1.1 现有导航（已核）

- 主导航（`frontend/src/pages/assistantModules.js` `PRODUCT_NAV_ITEMS`）：**待我处理**（路由 `inbox`）、任务、执行记录、对话、统计；底部：设置。
- 设置分区（`settingsNavigation.js`）：项目、AI 连接、通知与外部连接、通用、高级（运行维护、安全与权限、技能与工具、记忆、执行预设、处理记录）。

**命名冲突**：现有路由 `inbox` 是"待我处理"（首页）。新的消息收件箱不能再叫 `inbox`。

## 2. 消息页（`messages`）

### 2.1 布局

桌面两栏，沿用对话页的"左列表、右内容"骨架：

```
┌ 会话列表（侧栏宽度 --sidebar-width）┬ 会话详情 ───────────────────────────────┐
│ 筛选：来源 · 档位 · 有待处理         │ 头部：会话名 · 来源 · 档位选择 · 项目绑定  │
│ ─────────────────────────────────── │ Fact Strip：消息数 / 待处理 / 最近分拣 /   │
│ ● 张三（单聊）   DINGTALK  2 待处理  │            状态                           │
│   最后一条消息摘要 · 10:42           │ ─────────────────────────────────────── │
│ ○ 项目群         DINGTALK  CONTEXT   │ 时间线：消息按时间排列；每段分拣结论       │
│ …                                    │ 作为一条细线分隔的结论行插在段末尾         │
│                                      │ ─────────────────────────────────────── │
│                                      │ 底部操作：立即分拣                        │
└─────────────────────────────────────┴─────────────────────────────────────────┘
```

760px 以下单列：先列表，点进详情，头部带返回。

### 2.2 组件映射（只用规范已有组件）

| 元素 | 规范组件 |
| --- | --- |
| 会话列表项 | 5.4 侧边栏列表项：标题 `--text-md`，元数据行 mono `--text-2xs` |
| 来源、档位、结论类型标签 | 5.5 status-pill / 3.3 微标签；结论颜色映射：`reply_draft`、`todo` → warning；`triage_issue` → info；`ignore` → muted；`needs_review`、失败 → error；`remember` → muted |
| 会话状态 | 5.5 status-dot：`triaging` → info 脉冲；`collecting` → muted；`failed` → error；`waiting_model` → warning |
| 头部事实 | 5.6 Fact Strip |
| 消息 | 不用气泡（这些不是和玄武的对话）：发送方 mono 微标签 + 正文，本人消息左侧加 1px `--border-color-hover` 细边条区分，不用色块 |
| 结论行 | 细线分隔的行：结论 pill + 理由一句 + 关联对象链接（提案、待办、issue、记忆） |
| 档位选择、项目绑定 | 现有 select 控件 |
| 空状态 | 5.9：未启用任何插件时，lucide 图标 + "还没有启用来源插件" + secondary 按钮"去启用" |

主色实底按钮：本页不放（"立即分拣"用 secondary）。符合 0.3 单点强调。

### 2.3 交互

- 档位修改即时生效并记审计；从 `context_only` 改为 `triage` 时提示"只对之后的消息生效"，并提供"分拣最近 20 条"。
- 结论行上的操作：对 `ignore` 可"这是闲聊 → 以后这个人的闲聊都不用管"（TD-1 第 8 节）；对 `reply_draft` 跳到待我处理里的那张卡。
- 列表实时更新沿用现有 SSE 机制（与对话页相同的订阅方式），不新增轮询。

## 3. 待我处理（改造）

- **简报卡片**：页面顶部，一张 5.8.1 Request card 样式的卡，展示最近一份简报正文（折叠，默认显示前 4 行），右侧 secondary "手动生成"。
- **Inbox 来的事项**：沿用现有的 Request card 列表，新增卡片类型：
  - 回复草稿：卡内显示对方原话（引用样式）、草稿（可编辑 textarea，沿用现有表单控件）、`purpose`；操作 secondary"发送"、"丢弃"、"改了再发"。"发送"二次确认。
  - 待办：标题、到期；操作"完成"、"忽略"。
  - 提醒 / triage issue：沿用现有动作审批卡，按钮增加"批准，以后同类自动"（TD-3），对锁定为问的动作不显示。
  - 放开提示：一句话 + "以后自动" / "不用了"。
- **待确认记忆**：一行计数链接到记忆页的"待确认"筛选，不在首页逐条展示。
- 每张卡片的操作统一 secondary（规范 5.8.1 的 2026-10-15 补充）。

## 4. 设置 · 来源插件

### 4.1 列表

终端视窗容器（5.0）包住插件列表；每行：

| 列 | 内容 |
| --- | --- |
| 名称 | 插件名 + 版本（mono） |
| 来源 | `CATALOG` / `LOCAL`（未经审查，warning pill） |
| 状态 | status-dot + 健康状态（TD-2 7.3 五态） |
| 依赖 / 授权 | 依赖缺失、未登录时给出原因 |
| 操作 | 启用 / 停用开关；"设置" |

### 4.2 插件详情（抽屉，沿用 `IntegrationSettingsDrawer`）

分 Tabs（5.3）：

1. **概览**：说明、依赖检测结果、授权状态与"登录"（展示脱敏后的链接或设备码）、健康与最近错误（stderr 尾部，mono）、断档提示。
2. **设置**：按 manifest 的 `settings` 渲染表单；`role=self_id` 的字段单独标出"本人 ID（用于识别你自己发的消息）"；`secret` 类型只写不回显（沿用 API Key 字段的现有交互）。
3. **会话**：该来源的会话列表与档位（与消息页同一数据），可批量改档位；人的档位也在这里。
4. **授权**：该来源相关的放权规则（TD-3 的规则列表按来源过滤）。

保存设置后若插件在运行，提示"重启后生效"并提供 secondary "重启"。

## 5. 设置 · 通知与外部连接（改造）

在现有通知设置下新增三块，均为表单：

- **联系我**：渠道选择（已配置的飞书机器人 / Telegram / 指定插件会话），"发一条测试消息"，每日上限。
- **作息**：时区、工作日（7 个复选）、上下班时间、早晚报时间、下班行为两个开关。
- **简报**：启用、是否替代项目通知日报。

## 6. 设置 · AI 连接（改造）

- **模型与登录**：在现有 `PiProviderConnectionFlow` 上扩展：provider 列表来自 SDK，支持 OAuth 的显示"订阅登录"；登录过程中按 SDK 事件展示链接、设备码或输入框（TD-8 A3）；"从本机 Pi 导入"按钮与结果列表；"按用途选模型"表格（对话 / 分拣 / 记忆 / 简报 / 通知）。
- **Soul**：替换 `PersonaSettingsPanel`。左侧编辑器（沿用现有多行编辑器控件，等宽字体），右侧"Pi 实际看到的"编译预览；底部历史版本列表与回滚；保存带 revision 冲突提示。分拣摘要预览单独一块（只显示"关于我""我在意的"两节）。

## 7. 设置 · 高级（改造）

- **安全与权限 · 放权规则**：表格：动作、来源、范围、当前模式（select：问我 / 自动 / 禁止）、连续批准、自动次数、最近一次；顶部总开关、每日上限、"全部改回问我"（danger 按钮，二次确认）。
- **技能与工具**：技能库分两个区块"知识型""可执行"；知识型区块有"导入"入口，打开候选列表（来源、名称、描述、丢弃的文件清单、秘密拦截原因），逐个导入。
- **记忆**：按 TD-9 第 3 节；"导入"入口打开候选列表，逐条收进来 / 忽略，可先编辑。
- **处理记录 · 分拣调试**：按会话、按 run 查看分拣输入（上下文快照）、输出、校验结果、token；可标注"判断错了"及期望结论，写入 TD-1 的标注集。

## 8. 前端实现约束

- 新 CSS 只能引用 `tokens.css` 变量；先查 `components.css`，没有的组件才新增，并回写到 `docs/design-system/components.css` 与 `examples/index.html`（README "速查"）。本文预期**不需要新组件**：上面所有元素都映射到了 5.0–5.9。
- 新文件纳入现有样式合同测试（`Global.styles.test.js`、`Global.typescale-contract.json`、`Global.inlineStyles.test.js`），不加例外。
- 每页加组件测试（沿用 `*.test.js` 的模式）与页面模型测试（`*Model.js` + 测试）。
- 文案：中文说明，英文大写微标签（spec 第 8 节）。
