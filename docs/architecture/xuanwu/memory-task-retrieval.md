# 按任务召回记忆（Issue #969）

`memory_search` 与 `memoryContext.ts` 共用 `memoryRetrieval.ts`，只读现有 `pi_memory_items` 和停用/遗忘记录，不读取修订历史，也不新增存储、embedding 或模型配置。

- 输入兼容 `{query}`；可另传 `task_description`、`error_text`、`file_paths`、`version`。上下文投影使用本轮用户描述或绑定项目内的 Issue 描述，intake/domain skill 使用有界任务摘要。
- 默认隔离项目。全局用户偏好（含旧空 `scope_id`）保持原 authority 和作用域；不自动提升项目经验。普通策略按作用域保留，显式 query 则过滤策略正文。
- 每个作用域只检查最近 512 条，最多 10 个作用域窗口（最多两条绑定 Issue）；使用已有 scope 索引，每个窗口一条有界查询。最多处理 4096 字符输入、32 个检索词，跳过超过 16 Ki 字符的记忆正文。排序后最多保留 24 个候选，技术经验最多返回 3 条。
- 技术经验必须是有效结构化内容，项目、正向适用条件及版本均匹配，且未停用/遗忘、非低置信。版本不明、版本不同、只有旧文本或只命中 `failed_attempts` 不进入上下文。同义词表辅助中英文错误召回；文件和错误名仍可直接匹配。
- 版本检查保守匹配明确版本标识或完整版本说明，不推断版本范围兼容。复杂语义仍由原 Pi 会话判断；不为筛选单独发起模型调用。
- 初筛技术条目标记为 `text_candidate`。Pi 核对所有适用条件、版本和反例后，可以用相同检索上下文以及 `selection: [{id, revision, content_fingerprint, reason}]` 再筛选；`selection: []` 排除全部技术项，保留作用域策略。Host 重新查询并校验版本、指纹和停用规则，只允许候选子集；结果标记为 `pi_selected`。选择经过原 memory.search Action Gate/audit，不增加记忆权威或执行权限。
- 结果带 id、修订号、内容指纹、经验版本、来源、选择原因。沿用默认 900、最大 4000 的 token 预算；估算覆盖条目 JSON 元数据，对 CJK 保守计数。技术经验必须整条装入预算，避免截掉限制或反例。结果封装/固定提示词另属既有运行时预算。
- `retrieval.scan_limited` 表示窗口外可能仍有相关历史，不能据此声称搜遍历史。此阶段以有界成本和保守召回为先；不保证任意同义表达或旧窗口外经验的召回率。

本阶段只做本地自动验证。正式项目启用、真实模型筛选效果与最终体验验收由 Issue #973 完成。
